## 2. Table-by-Table Reference & Relationships

### Module 1: User Identity, Authentication & Access Control (RBAC)
1. **`users`**
   - **Purpose:** Central account record for Residents, Staff, and Administrators.
   - **Primary Key:** `id` (`BIGINT GENERATED BY DEFAULT AS IDENTITY`)
   - **Key Columns:** `email` (UNIQUE), `username` (UNIQUE), `password_hash` (`crypto.scryptSync`), `role`, `account_status`, `legacy_resident_uuid` (links to `resident_accounts.id`).
   - **Relationships:**
     - `1:1` with `user_profiles` (`user_id`)
     - `1:N` with `user_sessions`
     - `M:N` with `roles` via `user_roles`
2. **`user_profiles`**
   - **Purpose:** Extended profile metadata (name, contact number, purok, address, profile photo).
   - **Primary Key:** `user_id` (FK to `users.id` ON DELETE CASCADE)
   - **Foreign Keys:** `barangay_id` $\rightarrow$ `barangays.id` (SET NULL)
3. **`roles`**
   - **Purpose:** System role catalog (`resident`, `personnel`, `utility`, `administrator`).
   - **Primary Key:** `id`
   - **Relationships:** `M:N` with `permissions` via `role_permissions`.
4. **`user_roles`**
   - **Purpose:** Junction table assigning roles to users.
   - **Primary Key:** `(user_id, role_id)` (Composite PK prevents duplicates)
5. **`permissions`**
   - **Purpose:** Granular permission catalog (24 seeded permissions covering reports, dispatch, audit, users).
   - **Primary Key:** `id`
6. **`role_permissions`**
   - **Purpose:** Junction table mapping permissions to roles (53 seeded relationship rows).
   - **Primary Key:** `(role_id, permission_id)`
7. **`user_sessions`**
   - **Purpose:** Active login sessions storing SHA-256 token hashes.
   - **Primary Key:** `token_hash`
   - **Foreign Keys:** `user_id` $\rightarrow$ `users.id` (CASCADE)
8. **`oauth_accounts`**
   - **Purpose:** Third-party OAuth links (Google, Facebook).
   - **Primary Key:** `(provider, provider_user_id)`
9. **`oauth_states`**
   - **Purpose:** Short-lived CSRF state tokens for OAuth redirects.
   - **Primary Key:** `state_hash`
10. **`password_reset_tokens`**
    - **Purpose:** Single-use password recovery tokens with expiration timestamps.
    - **Primary Key:** `token_hash`

---

### Module 2: Geographic Master Reference
11. **`barangays`**
    - **Purpose:** Canonical reference table for all **31 official barangays** of Valencia City, Bukidnon.
    - **Primary Key:** `id`
    - **Key Columns:** `name` (UNIQUE), `latitude`, `longitude`, `bounds_geojson`, `population`.
    - **Relationships:** Referenced by `user_profiles`, `reports`, `incident_affected_areas`, `staff_barangay_assignments`.

---

### Module 3: Citizen Reports & Evidence
12. **`reports`**
    - **Purpose:** Ingests citizen power interruption complaints.
    - **Primary Key:** `id`
    - **Key Columns:** `report_code` (e.g., `VPR-XXXX`, UNIQUE), `reporter_id` (FK $\rightarrow$ `users.id`), `barangay_id` (FK $\rightarrow$ `barangays.id`), `purok`, `latitude`, `longitude`, `outage_type`, `status` (`Submitted`, `Verified`, `In Progress`, `Resolved`, `Rejected`).
    - **Relationships:**
      - `1:N` with `report_evidence`
      - `1:N` with `report_verifications`
      - `1:N` with `report_status_history`
      - `1:N` with `report_comments`
      - `M:N` with `incidents` via `incident_reports`
13. **`report_evidence`**
    - **Purpose:** Uploaded citizen images/videos of fallen poles, trees, or wires.
    - **Primary Key:** `id`
    - **Foreign Keys:** `report_id` $\rightarrow$ `reports.id` (CASCADE)
14. **`report_verifications`**
    - **Purpose:** Audit log of dispatcher review, confirming validity or duplicate status.
    - **Primary Key:** `id`
    - **Foreign Keys:** `report_id` $\rightarrow$ `reports.id`, `reviewer_id` $\rightarrow$ `users.id`
15. **`report_status_history`**
    - **Purpose:** Chronological status trail tracking lifecycle transitions.
    - **Primary Key:** `id`
    - **Foreign Keys:** `report_id` $\rightarrow$ `reports.id` (CASCADE), `changed_by` $\rightarrow$ `users.id`
16. **`report_comments`**
    - **Purpose:** Public and internal communication notes on specific reports.
    - **Primary Key:** `id`
    - **Foreign Keys:** `report_id` $\rightarrow$ `reports.id` (CASCADE), `user_id` $\rightarrow$ `users.id`

---

### Module 4: Master Incidents & Outage Updates
17. **`incidents`**
    - **Purpose:** Authoritative consolidated incident records created by dispatchers.
    - **Primary Key:** `id`
    - **Key Columns:** `incident_code` (e.g., `OUT-XXXX`, UNIQUE), `title`, `severity`, `incident_type` (`Scheduled` vs `Unexpected`), `estimated_restoration_time` (ETR), `status` (`Investigating`, `Verified`, `In Progress`, `Resolved`, `Closed`).
    - **Relationships:**
      - `1:N` with `incident_affected_areas`
      - `1:N` with `incident_assignments`
      - `1:N` with `outage_updates`
18. **`incident_reports`**
    - **Purpose:** Junction table linking multiple citizen reports (`VPR-XXXX`) to a master incident (`OUT-XXXX`).
    - **Primary Key:** `(incident_id, report_id)` (Composite PK prevents double-linking)
19. **`incident_affected_areas`**
    - **Purpose:** Junction table defining all barangays affected by an incident.
    - **Primary Key:** `id`
    - **Foreign Keys:** `incident_id` $\rightarrow$ `incidents.id` (CASCADE), `barangay_id` $\rightarrow$ `barangays.id`
20. **`incident_assignments`**
    - **Purpose:** Dispatch linkage assigning teams and field staff to master incidents.
    - **Primary Key:** `id`
    - **Foreign Keys:** `incident_id` $\rightarrow$ `incidents.id`, `team_id` $\rightarrow$ `repair_teams.id`, `staff_id` $\rightarrow$ `users.id`
21. **`outage_updates`**
    - **Purpose:** Public progress timeline logs displayed on citizen maps and dashboards.
    - **Primary Key:** `id`
    - **Foreign Keys:** `incident_id` $\rightarrow$ `incidents.id`, `updated_by` $\rightarrow$ `users.id`
22. **`scheduled_outages`**
    - **Purpose:** Pre-planned maintenance announcements with scheduled date/time windows.
    - **Primary Key:** `id`
    - **Foreign Keys:** `created_by` $\rightarrow$ `users.id`

---

### Module 5: Staff Dispatch & Field Linemen Tracking
23. **`repair_teams`**
    - **Purpose:** Operational repair crews, vehicle call signs, and real-time team coordinates.
    - **Primary Key:** `id`
    - **Key Columns:** `name`, `lead_lineman_id` (FK $\rightarrow$ `users.id`), `contact_number`, `current_latitude`, `current_longitude`.
24. **`repair_assignments`**
    - **Purpose:** Active field work orders dispatched to repair crews.
    - **Primary Key:** `id`
    - **Key Columns:** `team_id` (FK $\rightarrow$ `repair_teams.id`), `target_purok`, `dispatch_time`, `stage` (`En Route`, `Inspecting`, `Repairing`, `Completed`).
25. **`repair_assignment_evidence`**
    - **Purpose:** Post-repair completion photos uploaded by linemen directly from the field.
    - **Primary Key:** `id`
    - **Foreign Keys:** `assignment_id` $\rightarrow$ `repair_assignments.id` (CASCADE), `staff_id` $\rightarrow$ `users.id`
26. **`repair_assignment_location_confirmations`**
    - **Purpose:** GPS telemetry timestamp confirming that the lineman physically arrived on site.
    - **Primary Key:** `assignment_id` (`1:1` relationship)
27. **`staff_team_members`**
    - **Purpose:** Junction table defining which staff members belong to which repair team.
    - **Primary Key:** `(user_id, team_id)`
28. **`staff_barangay_assignments`**
    - **Purpose:** Junction table defining which barangays a technician is authorized to inspect.
    - **Primary Key:** `(user_id, barangay_id)`

---

### Module 6: Feedback, Notifications & Announcements
29. **`announcements`**
    - **Purpose:** Official broadcast advisories published by administrators.
    - **Primary Key:** `id`
    - **Foreign Keys:** `created_by` $\rightarrow$ `users.id`
30. **`notifications`**
    - **Purpose:** In-app notification inbox entries for users and staff.
    - **Primary Key:** `id`
    - **Foreign Keys:** `user_id` $\rightarrow$ `users.id` (CASCADE)
31. **`notification_preferences`**
    - **Purpose:** Per-user channel settings (SMS alerts, Email notifications, In-app push).
    - **Primary Key:** `id`
    - **Foreign Keys:** `user_id` $\rightarrow$ `users.id` (UNIQUE `1:1`)
32. **`feedback`**
    - **Purpose:** 1 to 5 star citizen feedback ratings submitted after power restoration.
    - **Primary Key:** `id`
    - **Foreign Keys:** `report_id` $\rightarrow$ `reports.id`, `user_id` $\rightarrow$ `users.id`

---

### Module 7: Auditing, Configuration & SMS Logs
33. **`settings`**
    - **Purpose:** System configuration key-value storage in JSON format.
    - **Primary Key:** `key` (`text`)
34. **`audit_logs`**
    - **Purpose:** Security and administrative activity trail (actor, action, IP address, timestamp).
    - **Primary Key:** `id`
    - **Foreign Keys:** `actor_id` $\rightarrow$ `users.id`
35. **`sms_logs`**
    - **Purpose:** Permanent delivery log of Semaphore SMS text notifications sent to residents and staff.
    - **Primary Key:** `id`

## 3. Runtime Persistence Tables (5 Tables)

These 5 tables are essential for **Render Cloud Persistence** and must **NOT** be dropped:
1. `app_snapshots`: Stores the latest gzip-compressed SQLite operational database snapshot.
2. `app_snapshots_backup`: Stores the fallback rolling backup snapshot.
3. `app_snapshot_files`: Stores uploaded report and evidence photos as binary `bytea`.
4. `resident_accounts`: Stores registered resident credentials (UUID primary key).
5. `resident_sessions`: Stores resident authentication tokens.

*Note on Integration:* The `users` table contains `legacy_resident_uuid UUID REFERENCES resident_accounts(id)`. This links the normalized schema to the runtime authentication store without duplicate accounts or lost passwords.

## 5. Security & Permission Synchronization SQL

To ensure that the application runtime user (`powerwatch_app_mvjwen4u`) can perform all CRUD operations on all 35 normalized tables in Neon, execute the following script in the **Neon SQL Editor** as `neondb_owner`:

```sql
-- 1. Remove unnecessary sample table
DROP TABLE IF EXISTS playing_with_neon;

-- 2. Grant full operational permissions to the application role
GRANT USAGE ON SCHEMA public TO powerwatch_app_mvjwen4u;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO powerwatch_app_mvjwen4u;
GRANT USAGE, SELECT, UPDATE ON ALL SEQUENCES IN SCHEMA public TO powerwatch_app_mvjwen4u;

-- 3. Ensure future tables and sequences automatically grant permissions
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO powerwatch_app_mvjwen4u;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT USAGE, SELECT, UPDATE ON SEQUENCES TO powerwatch_app_mvjwen4u;
```
